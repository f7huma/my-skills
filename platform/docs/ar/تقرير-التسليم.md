# تقرير التسليم — منصة مكتب فيصل حميضان الحميضان للمحاماة

التاريخ: 2026-11-04 · الفرع: `add-design-skills` · المجلد: `platform/`

## 1. القرار التقني
المستودع كان مستودع مهارات بلا تطبيق، فأنشأت تطبيقًا موحدًا جديدًا: **Laravel 13.40 (PHP 8.3) + PostgreSQL + Inertia v3 + React 19 + TypeScript + Tailwind 4**، مع طوابير Laravel (قاعدة البيانات) للفحص، والجدولة للنسخ والتنبيهات والفحوص، وmPDF لتوليد PDF عربي على الخادم. لم أضف Redis لتقليل مكونات التشغيل؛ يمكن إضافته لاحقًا دون تغيير الكود.

## 2. ما نُفّذ
**الحسابات والصلاحيات:** دعوات أحادية الاستخدام محدودة المدة، أدوار محامٍ/عميل، عضويات بصلاحيتي متابعة ومطالبات منفصلتين وتعدد مستخدمي المنشأة، تعطيل وإبطال جلسات فوري، مصادقة ثنائية TOTP إلزامية للمحامي في الإنتاج مع رموز استرداد، إعادة تعيين كلمة المرور برابط من المحامي، سجل تدقيق للإضافة فقط.

**لوحة المحامي:** قائمة إنجاز الأسبوع (متأخر/اليوم/بقية الأسبوع/بانتظار موعد) مستمدة آليًا من الجلسات والمهام والمذكرات ومتابعات التنفيذ والعدادات مع شريط أيام الأسبوع، المطالبات الواردة، الجلسات القادمة، العدادات، الوكالات القريبة من الانتهاء، بحث سريع في العملاء، وبحث داخلي بأرقام القضايا والطلبات والوكالات والأسماء والأطراف.

**العملاء والوكالات:** صفحة العميل (فرد/منشأة، الهوية أو الرقم الموحد والسجل، العنوان، التواصل، عدادات محسوبة تميّز الموقوفة/المشطوبة)، تبويبات الملفات والوكالات والقضايا والتنفيذ والمطالبات وحسابات البوابة، وكالات مستقلة متعددة بنافذة تنبيه قابلة للضبط ولا تُستبدل.

**القضية:** مسودة بأقل البيانات، البدء من أي مرحلة (مدعٍ أو مدعى عليه)، فصل المرحلة/حالة العمل/النتيجة، تبويبات تظهر بحسب السجل مع «إضافة إجراء»، تراضي (طلبات وجلسات ونتيجة وصلح بمبلغ متفق عليه أو تعذر ← ناجز مع مهمة لائحة مرة واحدة)، ناجز (رقم طلب التقييد ≠ رقم القضية، الإعادة للاستكمال وإعادة التقديم مع السجل)، الجلسات (حضور، نتيجة، ضبط، توجيهات، تأجيل/تعديل/إلغاء مع معاينة الأثر وحفظ السبب، إكمال مع مهام متعددة باستحقاق صريح أو نسبي أو مرتبط بالجلسة القادمة)، محرر مذكرات عربي بإصدارات وحالات وفصل الاعتماد عن الإيداع وطباعة، الحكم بأنواعه مع الاستكمال والصك والاعتراض والنهائية الصريحة وقرار التنفيذ.

**المواعيد والتنفيذ:** شاشة موحدة بدرجات اليقين وأساس الحساب والمتبقي والهجري، أيام عمل وتقويم إجازات قابل للمراجعة، قواعد ذات إصدارات لا تعمل قبل الاعتماد، تنفيذ مالي/مباشر منفصل عن نوع السند مع حقول مشروطة، تواريخ الوقائع منفصلة، تسجيل «قرار 34/46» من واقع المستند، طلبات الإجراء بمهلة إعادة قابلة للضبط ومن آخر طلب مماثل، متابعة أسبوعية اختيارية، سجل تحصيل بعمليات مستقلة ومجاميع لكل عملة بلا ازدواج.

**بوابة العميل والمطالبات:** القضايا والتنفيذ والحالة وآخر تحديث معتمد والمحصّل، نموذج مطالبة بمسودة وتمييز «موكل المكتب» عن «المطالب ضده» ومرفقات بحسب الطرف وسبب نقص المستند وعلامة «ناقص مستند»، مرجع وحالة «قيد الدراسة»، طلب استكمال، تحويل إلى قضية أو تنفيذ بلا ازدواج مع بقاء الارتباط، إغلاق بسبب.

**التقارير:** تقرير عميل وتقرير قضية، نسخة عميل من الحقول المسموحة ونسخة داخلية بخيارات، معاينة ثم PDF بـ A4 وترقيم ورؤوس وتذييل بالشعار والترخيص والتاريخ الهجري.

**الملفات والتشغيل:** تشفير على مستوى الملف بمفتاح منفصل، حجر وفحص ClamAV محلي وحجب عند التعطل، تفويض كل تنزيل، نسخ احتياطي مشفر متسق مع بيان سلامة واحتفاظ ووجهة منفصلة، تحقق، استعادة معزولة مع فحص الدخول وارتباط الملفات، صفحة حالة النظام وتنبيهات، Docker Compose (Caddy/HTTPS، web، worker، scheduler، Postgres داخلي، ClamAV، وحدات دائمة، بيئة معاينة، بيئة اختبار استعادة)، سكربتات النشر والتراجع، CI بالبوابات.

## 4. ما لم يُشغَّل أو لم يكتمل — لا يُعد ناجحًا
- **بناء صورة Docker كاملة:** نجحت مرحلتا الواجهة وComposer، وتوقفت مرحلة التشغيل لأن مرايا Debian محجوبة في بيئة العمل. يجب تشغيل `docker compose build` على الخادم.
- **فحوص CI** (gitleaks، semgrep، trivy للملفات والصورة، OWASP ZAP baseline): مكتوبة في `.github/workflows/platform-ci.yml` ولم تُشغَّل هنا؛ تعمل عند الدفع إلى GitHub وتمنع وظيفة `ready-to-deploy` عند الفشل.
- **ClamAV حقيقي:** الاختبارات استخدمت محركًا تجريبيًا يكتشف EICAR ويحاكي التعطل. بروتوكول clamd مكتوب ولم يُختبر أمام clamd فعلي.
- **المراجع النظامية وصفحات Hostinger:** لم أتمكن من فتح أي من الروابط المرجعية (أم القرى، وزارة العدل، سدايا، Hostinger) — حجب على مستوى الشبكة. لذلك القواعد الافتراضية للتنفيذ والاعتراض مسودات غير مطبقة، ومهل إعادة الطلبات فارغة، والإجازات تقديرية.
- **البريد:** يعمل بمشغّل `log` محليًا؛ يحتاج إعداد خادم بريد المكتب.
- **مهارة 21st.dev:** غير مثبتة فلم تُستخدم. **ui-ux-pro-max:** لم تُستدعَ. **Impeccable:** خطافها الآلي فقط.
- لا أصف التطبيق بأنه خالٍ من الثغرات.

## 5. أوامر التشغيل
محليًا: `docs/ar/01-التشغيل-المحلي.md`. على الخادم: `docs/ar/02-النشر-على-Hostinger.md`. أهمها:
```bash
php artisan office:invite-lawyer <email> "<name>"   # المحامي الأول
php artisan backup:run --verify | backup:list | backup:verify | backup:restore-test <name>
php artisan ops:check | ops:security-check
php artisan files:generate-key [--backup] | files:rotate-key | files:rescan-pending
./scripts/deploy.sh <tag> | ./scripts/rollback.sh | ./scripts/restore-test.sh <name>
```

## 6. ما بقي للتحقق على خادم Hostinger
بناء الصورة وتشغيل كل الخدمات؛ إصدار شهادة TLS للدومين المؤقت ثم الدائم؛ عمل ClamAV وتحديث تواقيعه ورفض EICAR؛ نبض العامل والجدولة؛ إرسال البريد وقناة التنبيه؛ تركيب الوجهة المنفصلة للنسخ؛ تفعيل نسخ Hostinger وتوثيق خصائصه؛ اختبار استعادة معزول ناجح مع دخول وفتح مرفق؛ نجاح CI.

## 7. شروط تفعيل بيانات العملاء الحقيقية (ملخص — التفصيل في 07-قائمة-الإطلاق)
1. التحقق من إعداد الاستضافة ومواضع حفظ البيانات والنسخ ومعالجتها، ومتطلبات نقل البيانات الشخصية إن كان أي منها خارج المملكة.
2. نجاح الاستعادة على بيئة معزولة (قاعدة + مرفقات) مع تجربة الدخول وفتح المرفقات.
3. مراجعة أمنية لإعداد الإنتاج (`ops:security-check` بلا إخفاق + مراجعة بشرية للخادم والمفاتيح) ونجاح بوابات CI دون ثغرات عالية أو حرجة.
4. مراجعة قواعد المواعيد وتقويم الإجازات ومهل طلبات الإجراء من قبل المحامي.
