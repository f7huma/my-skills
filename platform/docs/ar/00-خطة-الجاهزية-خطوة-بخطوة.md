# خطة الجاهزية خطوة بخطوة

من الوضع الحالي إلى تشغيل المنصة ببيانات حقيقية. نفّذ المراحل بالترتيب، ولا تنتقل لمرحلة قبل نجاح «علامة النجاح» في السابقة.

> **ملاحظة صادقة عن أسماء القوائم:** لم أستطع فتح موقع Hostinger من بيئة العمل، فأسماء الأزرار في لوحة Hostinger أدناه وصف عام وقد تختلف قليلًا في لوحتك. المهم هو الشيء المطلوب، لا الاسم الحرفي.

**أين تُكتب الأوامر؟** كل سطر يبدأ بـ `ssh` أو `docker` أو `php` أو `git` يُكتب في **الطرفية (Terminal)**:
- على ويندوز: افتح «Windows PowerShell» من قائمة ابدأ.
- على ماك: افتح تطبيق «Terminal» من البحث (Spotlight).

بعد الدخول للخادم بأمر `ssh` تُكتب بقية الأوامر في النافذة نفسها.

## المرحلة 0: قبل الشراء (يوم واحد)

### الخطوة 0.1: قرار موقع البيانات
- **ماذا:** تحديد البلد الذي سيكون فيه الخادم (مركز البيانات).
- **أين:** صفحة باقات VPS في موقع Hostinger. عند الشراء يُطلب اختيار الموقع (Location / Data center).
- **لماذا:** إن كان خارج المملكة فعليك مراجعة «لائحة نقل البيانات الشخصية إلى خارج المملكة» في موقع سدايا (dgp.sdaia.gov.sa). وثّق القرار كتابيًا.
- **علامة النجاح:** قرار مكتوب بالموقع وسببه.

### الخطوة 0.2: الدومين
- **ماذا:** دومين المكتب الدائم، ونطاق فرعي مؤقت للمعاينة مثل `preview.دومينك`.
- **أين:** عند الجهة التي اشتريت منها الدومين (Hostinger أو غيرها)، في قسم «DNS» أو «إدارة المنطقة DNS Zone».
- **علامة النجاح:** تستطيع الدخول لصفحة DNS وإضافة سجل.

### الخطوة 0.3: حساب GitHub
- **ماذا:** المستودع `f7huma/my-skills` موجود والكود على الفرع `add-design-skills`.
- **أين:** github.com ← المستودع ← تبويب **Actions**.
- **علامة النجاح:** آخر تشغيل لـ `platform-ci` بعلامة خضراء ✓.
  - إن كانت حمراء ✗ فأرسل لي رابطها، وسأصلحها.
  - يفضّل دمج الفرع في `main` عبر Pull Request حين تكون خضراء.

## المرحلة 1: شراء وتجهيز الخادم (ساعة إلى ساعتين)

### الخطوة 1.1: شراء VPS
- **أين:** موقع Hostinger ← VPS.
- **ماذا تختار:**
  - **الذاكرة (RAM):** 4GB على الأقل، والأفضل 8GB. فاحص الفيروسات وحده يحتاج حوالي 1.5GB.
  - **القرص:** 100GB أو أكثر.
  - **نظام التشغيل:** Ubuntu 24.04.
  - **الموقع:** ما قررته في الخطوة 0.1.
- أثناء الإعداد سيطلب كلمة مرور root أو مفتاح SSH. احفظها في خزنة كلمات المرور.
- **علامة النجاح:** في لوحة Hostinger (hPanel ← VPS) يظهر الخادم «يعمل»، ومعه **عنوان IP**. انسخ العنوان.

### الخطوة 1.2: الدخول للخادم
- **أين:** الطرفية على جهازك.
```bash
ssh root@<عنوان-IP>
```
- **علامة النجاح:** يظهر سطر مثل `root@srv...:~#`.

### الخطوة 1.3: تحديث الخادم وتثبيت Docker والجدار الناري
- **أين:** نفس الطرفية بعد الدخول. انسخ الأسطر كما هي:
```bash
apt update && apt -y upgrade
apt -y install git ufw unattended-upgrades
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
curl -fsSL https://get.docker.com | sh
docker --version
```
- **علامة النجاح:** يظهر رقم إصدار Docker.
- تحقق أيضًا من وجود «Firewall» في لوحة Hostinger، وإن كان موجودًا فاسمح بالمنافذ 22 و80 و443 فقط.

### الخطوة 1.4: تفعيل نسخ Hostinger الاحتياطي (طبقة إضافية)
- **أين:** hPanel ← VPS ← خادمك ← قسم النسخ الاحتياطي (Backups / Snapshots).
- **ماذا:** فعّل النسخ التلقائي إن كان متاحًا في باقتك، ودوّن:
  - كل كم يوم يُنسخ؟
  - كم يبقى محفوظًا؟
  - هل الاستعادة تستبدل الخادم كله؟
- **علامة النجاح:** إجابات الأسئلة الثلاثة مكتوبة عندك.

## المرحلة 2: ربط الدومين (10 دقائق + انتظار حتى ساعات)

### الخطوة 2.1: سجل المعاينة
- **أين:** صفحة DNS لدومينك (الخطوة 0.2).
- **ماذا:** أضف سجلًا من نوع **A**:
  - الاسم (Name/Host): `preview`
  - القيمة (Points to): عنوان IP للخادم
  - TTL: الافتراضي
- **علامة النجاح:** على جهازك نفّذ `ping preview.دومينك` فيظهر عنوان IP الخادم. قد يحتاج ذلك من دقائق إلى ساعات.

> سجل الدومين الدائم (`@` أو `www`) لا تضفه الآن؛ مكانه المرحلة 7.

## المرحلة 3: تشغيل بيئة المعاينة (ساعة)

بيئة المعاينة نسخة كاملة للتجربة ببيانات وهمية، محمية بكلمة مرور قبل شاشة الدخول.

### الخطوة 3.1: تنزيل الكود
- **أين:** طرفية الخادم.
```bash
cd /opt && git clone https://github.com/f7huma/my-skills.git humaidan
cd /opt/humaidan && git checkout add-design-skills
cd platform
```
إن كان المستودع خاصًا فسيطلب اسم مستخدم GitHub ورمز وصول. أنشئ الرمز من github.com ← صورتك ← Settings ← Developer settings ← Personal access tokens، بصلاحية قراءة المستودع فقط.

### الخطوة 3.2: بناء الصورة
```bash
docker compose build
```
- **علامة النجاح:** ينتهي الأمر بدون كلمة `ERROR`.
- **إن فشل:** انسخ آخر 30 سطرًا وأرسلها لي. هذه هي الخطوة التي لم أستطع تجربتها في بيئتي.

### الخطوة 3.3: توليد المفاتيح وكلمات المرور
- **أين:** طرفية الخادم.
- **ماذا تفعل:** نفّذ الأمر التالي **خمس مرات**، واحفظ كل ناتج في خزنة كلمات المرور تحت عنوان «معاينة»:
```bash
echo "base64:$(openssl rand -base64 32)"
```
- **ماذا تسمّي النواتج الخمسة:**
  - الأول: `APP_KEY`.
  - الثاني: `FILES_ENCRYPTION_KEY`.
  - الثالث: `BACKUP_ENCRYPTION_KEY`.
  - الرابع (احذف منه كلمة `base64:`): كلمة مرور قاعدة البيانات.
  - الخامس (احذف منه كلمة `base64:`): كلمة حماية المعاينة.
- **ولّد بصمة كلمة حماية المعاينة:**
```bash
docker run --rm caddy:2.10-alpine caddy hash-password -p 'كلمة-حماية-المعاينة'
```
- **علامة النجاح:** خمس قيم وبصمة واحدة محفوظة في الخزنة.

### الخطوة 3.4: ملفات الإعداد
```bash
cp .env.example .env.preview
nano .env.preview
```
(داخل nano: عدّل بالأسهم، ثم احفظ بـ Ctrl+O ثم Enter، واخرج بـ Ctrl+X)

عدّل هذه الأسطر:
```
APP_ENV=preview
APP_DEBUG=false
APP_URL=https://preview.دومينك
APP_KEY=<المفتاح الأول>
APP_NOINDEX=true
SYNTHETIC_DATA_ONLY=true
DB_HOST=db
DB_DATABASE=humaidan
DB_USERNAME=humaidan
DB_PASSWORD=<كلمة مرور القاعدة>
SESSION_SECURE_COOKIE=true
SCANNER_DRIVER=clamav
FILES_ENCRYPTION_KEY=<المفتاح الثاني>
BACKUP_ENCRYPTION_KEY=<المفتاح الثالث>
```
ثم أنشئ ملف متغيرات Compose:
```bash
nano .env
```
واكتب فيه:
```
COMPOSE_PROJECT_NAME=humaidan-preview
APP_ENV_FILE=.env.preview
APP_DOMAIN=preview.دومينك
ACME_EMAIL=<بريد المكتب>
DB_PASSWORD=<نفس كلمة مرور القاعدة>
PREVIEW_BASIC_USER=preview
PREVIEW_BASIC_HASH=<البصمة الناتجة>
```
ثم:
```bash
chmod 600 .env .env.preview
```
> سطر `COMPOSE_PROJECT_NAME` ضروري: يجعل قاعدة بيانات المعاينة وملفاتها منفصلة تمامًا عن الإنتاج.

### الخطوة 3.5: التشغيل
```bash
docker compose -f docker-compose.yml -f docker-compose.preview.yml up -d db clamav
sleep 60
docker compose -f docker-compose.yml -f docker-compose.preview.yml run --rm app migrate
docker compose -f docker-compose.yml -f docker-compose.preview.yml run --rm app php artisan db:seed --force
docker compose -f docker-compose.yml -f docker-compose.preview.yml up -d
docker compose -f docker-compose.yml -f docker-compose.preview.yml ps
```
- **علامة النجاح:** كل الخدمات `running` أو `healthy`.
  - الخدمات هي: caddy وapp وworker وscheduler وdb وclamav.
  - ClamAV يحتاج بضع دقائق في أول تشغيل لتنزيل التواقيع.

### الخطوة 3.6: الدخول من المتصفح
- **أين:** المتصفح ← `https://preview.دومينك`.
- يظهر أولًا طلب اسم مستخدم وكلمة مرور (حماية المعاينة): `preview` وكلمة الحماية.
- ثم شاشة دخول المنصة: `lawyer@example.test` / `Demo-Pass-2026`.
- **علامة النجاح:**
  - قفل HTTPS سليم في شريط العنوان.
  - تظهر «إنجاز الأسبوع».

## المرحلة 4: الفحوص على الخادم (نصف ساعة)

اختصار لتقليل الكتابة:
```bash
alias dcp='docker compose -f docker-compose.yml -f docker-compose.preview.yml'
```

### الخطوة 4.1: حالة النظام
- **أين:** في المنصة: القائمة الجانبية ← **إدارة المكتب ← حالة النظام** ← زر «تشغيل الفحوص الآن».
- **علامة النجاح:**
  - «فحص الملفات» سليم.
  - «الطوابير والعامل» سليم بعد 5–10 دقائق من التشغيل.
  - «شهادة TLS» سليم.
  - «النسخ الاحتياطي» يتحسن بعد الخطوة 4.3.

### الخطوة 4.2: اختبار فاحص الفيروسات
- **أين:** طرفية الخادم.
```bash
dcp exec app php artisan ops:scanner-selftest
```
- **ماذا يحدث:** يرسل الأمر نص الاختبار القياسي EICAR مباشرة إلى ClamAV. هذا النص غير ضار ومصمم لاختبار برامج الحماية.
- **علامة النجاح:** تظهر الأسطر الثلاثة:
  - `EICAR: infected (clamav)`.
  - `ملف سليم: clean`.
  - «محرك الفحص يعمل».
- **إن ظهر `error`:** ClamAV ما زال يحمّل التواقيع. انتظر 5 دقائق وأعد المحاولة.
- **بعدها جرّب الرفع الفعلي:**
  - ادخل المنصة ← العملاء ← أي عميل ← تبويب «الملفات» ← ارفع ملف PDF عاديًا.
  - يجب أن يظهر «قيد الفحص» ثم «سليم» خلال دقيقة.

### الخطوة 4.3: النسخ الاحتياطي واختبار الاستعادة
```bash
dcp exec app php artisan backup:run --verify
dcp exec app php artisan backup:list
```
انسخ اسم النسخة (يبدأ بـ `backup-`)، ثم:
```bash
cp .env.restore-test.example .env.restore-test
nano .env.restore-test     # ضع APP_KEY و FILES_ENCRYPTION_KEY و BACKUP_ENCRYPTION_KEY نفسها
./scripts/restore-test.sh <اسم-النسخة>
```
- **علامة النجاح:** جدول يظهر `ok = نعم`، و`missing_files = 0`، و`corrupt_files = 0`.

### الخطوة 4.4: المراجعة الأمنية الآلية
```bash
dcp exec app php artisan ops:security-check
```
في المعاينة سيفشل بعض البنود عمدًا، مثل وجود حسابات تجريبية لأن البيئة ليست إنتاجًا. الهدف هنا أن تتعرف على القائمة فقط.

## المرحلة 5: التجربة الفعلية (أسبوع)

- **أين:** `https://preview.دومينك`، بالحسابات التجريبية الموجودة في `01-التشغيل-المحلي.md`.
- **ماذا:** اعمل كأنه يوم عمل حقيقي بأسماء وهمية:
  1. أضف عميلًا ووكالة.
  2. أنشئ قضية من الصلح، ثم تعذّر صلح وانتقال لناجز.
  3. جدول جلسة، ثم أجّلها، ثم أكملها مع ضبط.
  4. اكتب مذكرة واعتمدها وسجّل إيداعها.
  5. سجّل حكمًا والصك منتظر، ثم صدوره، ثم تنفيذًا وتحصيلًا جزئيًا.
  6. ادخل بحساب `cfo@example.test` وأرسل مطالبة بمرفقات، ثم حوّلها من حساب المحامي.
  7. صدّر تقرير عميل وتقرير قضية واطبعهما.
  8. جرّب من جوالك.
- **سجّل كل ملاحظة** (شيء غير واضح، أو حقل ناقص، أو خطأ) في قائمة واحدة وأرسلها لي.
- **علامة النجاح:** أسبوع بلا ملاحظات جوهرية متبقية.

## المرحلة 6: الإعدادات القانونية (يومان، عملك أنت)

### الخطوة 6.1: قواعد المواعيد
- **أين:** المنصة ← **الإعدادات ← قواعد المواعيد**.
- **ماذا:**
  - راجع نظام التنفيذ (المواد 14 و18 و36) ولائحته من أم القرى.
  - إن تأكدت من مهلة الخمسة أيام عمل ونقطة بدايتها، اضغط «اعتماد بعد المراجعة».
  - إن احتاجت تعديلًا فاضغط «إصدار جديد» وأدخل القيم الصحيحة والمصدر.
- افعل الشيء نفسه لقاعدة الاعتراض، أو اتركها مسودة وأدخل مواعيد الاعتراض يدويًا.
- **علامة النجاح:** كل قاعدة إما «معتمدة» عن قناعة أو «مسودة» عن قصد.

### الخطوة 6.2: تقويم الإجازات

- **ماذا:** صحّح تواريخ العيدين لسنة 2026 و2027 وفق الإعلان الرسمي، واضغط «اعتماد» لكل يوم، وأضف إجازات المكتب.
- **علامة النجاح:** لا يظهر «لم يُراجع» على أي يوم.

### الخطوة 6.3: مهل طلبات الإجراء
- **أين:** الإعدادات ← **أنواع طلبات الإجراء**.
- **ماذا:** لكل خدمة (الإفصاح، تحويل المبلغ المحجوز، …) ضع مهلة إعادة الطلب من شروط الخدمة في ناجز أو وزارة العدل، أو اتركها فارغة إن لم توجد.

### الخطوة 6.4: نافذة الوكالات
- **أين:** الإعدادات ← **عام**. القيمة الافتراضية 30 يومًا.

> هذه الإعدادات تُنفَّذ في المعاينة للتجربة، ثم تُعاد في الإنتاج (الخطوة 7.6). البيانات لا تنتقل بين البيئتين.

## المرحلة 7: الإنتاج (نصف يوم)

### الخطوة 7.1: سجل الدومين الدائم
- **أين:** صفحة DNS لدومينك.
- **ماذا:** سجل **A** بالاسم `@` (أو `app` إن أردت `app.دومينك`) يشير لعنوان IP الخادم.

### الخطوة 7.2: وجهة النسخ المنفصلة
- **ماذا:** مكان ثانٍ للنسخ **ليس على قرص الخادم نفسه**، تحت حساب المكتب.
  - مثال: VPS صغير ثانٍ أو تخزين شبكي في الموقع الذي اعتمدته في الخطوة 0.1.
- **أين:** على الخادم، بعد تجهيز الوجهة:
```bash
apt -y install sshfs
mkdir -p /mnt/humaidan-offsite
sshfs backup@<عنوان-الوجهة>:/backups /mnt/humaidan-offsite -o allow_other,reconnect
```
- **علامة النجاح:** `ls /mnt/humaidan-offsite` يعمل.
  - لتركيب دائم بعد إعادة التشغيل أضف السطر إلى `/etc/fstab`. إن احتجت ذلك أجهّز لك السطر.

### الخطوة 7.3: مفاتيح جديدة للإنتاج
- كرر الخطوة 3.3، أول أربعة أوامر فقط، لتوليد **مفاتيح جديدة مختلفة تمامًا** عن المعاينة، وكلمة مرور قاعدة جديدة.
- احفظها في الخزنة بعنوان «إنتاج»، **ونسخة ثانية في مكان منفصل**. فقدان المفاتيح يعني فقدان الملفات والنسخ.

### الخطوة 7.4: ملفات الإنتاج
لتجنب الخلط بين البيئتين، ضع الإنتاج في مجلد مستقل:
```bash
cd /opt && git clone https://github.com/f7huma/my-skills.git humaidan-prod
cd /opt/humaidan-prod && git checkout add-design-skills && cd platform
cp .env.example .env.production && nano .env.production
```
الأسطر المطلوبة:
```
APP_ENV=production
APP_DEBUG=false
APP_URL=https://دومينك
APP_KEY=<مفتاح جديد>
DB_HOST=db
DB_DATABASE=humaidan
DB_USERNAME=humaidan
DB_PASSWORD=<كلمة جديدة>
SESSION_SECURE_COOKIE=true
SESSION_ENCRYPT=true
MFA_REQUIRED_FOR_LAWYER=true
SCANNER_DRIVER=clamav
FILES_ENCRYPTION_KEY=<جديد>
BACKUP_ENCRYPTION_KEY=<جديد>
BACKUP_OFFSITE_PATH=/mnt/offsite
OPS_ALERT_MAIL=<بريد المكتب>
MAIL_MAILER=smtp
MAIL_HOST=<خادم بريد المكتب>
MAIL_PORT=587
MAIL_USERNAME=<...>
MAIL_PASSWORD=<...>
MAIL_FROM_ADDRESS=<no-reply@دومينك>
```
إعدادات البريد تأخذها من مزود بريد المكتب. إن كان البريد من Hostinger فتجدها في hPanel ← Emails ← إعدادات الاتصال.

ثم ملف متغيرات Compose:
```bash
nano .env
```
```
COMPOSE_PROJECT_NAME=humaidan
APP_ENV_FILE=.env.production
APP_DOMAIN=دومينك
ACME_EMAIL=<بريد المكتب>
DB_PASSWORD=<نفس كلمة القاعدة>
BACKUP_OFFSITE_MOUNT=/mnt/humaidan-offsite
```
ثم:
```bash
chmod 600 .env .env.production
```

> **مهم:** المعاينة والإنتاج على خادم واحد لا يستطيعان معًا استخدام المنفذ 443.
> - **الأبسط:** أوقف المعاينة الآن:
>   ```bash
>   cd /opt/humaidan/platform && docker compose -f docker-compose.yml -f docker-compose.preview.yml down
>   ```
> - إن أردت إبقاءها تعمل بجانب الإنتاج، أخبرني لأجهّز وكيلًا واحدًا يخدم الدومينين.

### الخطوة 7.5: تشغيل الإنتاج
```bash
cd /opt/humaidan-prod/platform
docker compose build
docker compose up -d db clamav && sleep 60
docker compose run --rm app migrate
docker compose run --rm app php artisan db:seed --class='Database\Seeders\ReferenceDataSeeder' --force
docker compose up -d
docker compose ps
```
**لا تشغّل `db:seed` بدون `--class` في الإنتاج.** الأمر الصحيح أعلاه يضيف البيانات المرجعية فقط، وهي التصنيفات وأنواع الإجراءات والإجازات والقواعد كمسودات.

### الخطوة 7.6: حساب المحامي الأول والمصادقة الثنائية
```bash
docker compose exec app php artisan office:invite-lawyer <بريدك> "فيصل حميضان الحميضان"
```
- يظهر رابط. افتحه في المتصفح وعيّن كلمة مرور قوية من 12 حرفًا أو أكثر.
- سيُطلب منك فورًا تفعيل **المصادقة الثنائية**:
  1. ثبّت على جوالك تطبيق Microsoft Authenticator أو Google Authenticator.
  2. امسح الرمز المعروض.
  3. أدخل الرقم.
  4. **اطبع رموز الاسترداد أو احفظها في الخزنة.**
- كرر إعدادات المرحلة 6 هنا في الإنتاج.
- **علامة النجاح:** تدخل بكلمة المرور ثم رمز الجوال.

### الخطوة 7.7: الفحوص النهائية
```bash
docker compose exec app php artisan backup:run --verify
docker compose exec app php artisan ops:check
docker compose exec app php artisan ops:security-check
```
ثم اختبار استعادة على النسخة الجديدة، كما في الخطوة 4.3: انسخ `.env.restore-test.example` إلى `.env.restore-test` وضع فيه **مفاتيح الإنتاج**، ثم:
```bash
./scripts/restore-test.sh <اسم-النسخة>
```
- **علامة النجاح:**
  - `ops:security-check` يقول «اكتملت المراجعة» بلا ✗.
  - اختبار الاستعادة `ok = نعم`.
  - صفحة حالة النظام كلها خضراء.
  - وصلتك رسالة تنبيه تجريبية على البريد: جرّبها بإيقاف العامل مؤقتًا `docker compose stop worker`، ثم انتظر الفحص الساعي، ثم أعده `docker compose start worker`.

## بعد الإطلاق: التشغيل الدوري
| متى | ماذا | أين |
|---|---|---|
| يوميًا (تلقائي) | نسخ احتياطي، تنبيهات المواعيد، فحص الملفات | لا شيء منك؛ راقب بريد التنبيهات |
| أسبوعيًا | نظرة على «حالة النظام» | المنصة ← إدارة المكتب ← حالة النظام |
| شهريًا | اختبار استعادة معزول | الطرفية: `./scripts/restore-test.sh` |
| عند كل تحديث | `./scripts/deploy.sh <الإصدار>`، وعند المشكلة `./scripts/rollback.sh` | الطرفية في `/opt/humaidan-prod/platform` |
| سنويًا | مراجعة الإجازات وقواعد المواعيد | المنصة ← الإعدادات |
